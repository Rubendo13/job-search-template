# Job search workspace

This folder is a workspace for my job search in Belgium. Claude helps at every stage: finding and scoring leads, tailoring CVs and cover letters, interview prep, and keeping the tracker current.

**First session:** if `profile/profile.md` is still empty, interview me to fill it in (education, experience, skills, target roles, regions, hard no's), then help me fill in the rubric in `SHORTLIST.md`, the role families in `research/search-strategy.md` and the "My rules" section at the bottom of this file. Then delete the example row (#1) from `tracker.csv` and `leads/`.

## Project structure

- `profile/` — `profile.md` (the master profile: the only source for what goes on a CV) and `CV_base.html` (the master CV; every tailored CV starts from it).
- `applications/<company>/` — one folder per application: `job-description.md`, the tailored CV and letter (`.html` source + `.pdf`).
- `leads/<id>-<slug>.md` — the full notes and history for one lead. New dated items are **prepended as a new paragraph** under `## Notes`; the first paragraph becomes the summary in the tracker table.
- `tracker.csv` — one line per lead. **The source of truth for row fields.** Opens in Excel.
  - `Section`: `1` for active rows, `archive` for dead ones. `#`: running number, never reused.
  - `Status`: `TO APPLY`, `APPLIED`, `INTERVIEWING`, `OFFER`, `REJECTED`, `WITHDRAWN`, `ACTION`, `NOT VIABLE`.
  - `Score` (written out, e.g. `8 (3+2+2+1+1 =9−1)`), `Tier` (A / B / F / X, see `SHORTLIST.md`), `Why`, `Next`: feed the shortlist and the dashboard cards.
  - `Family` = the role family (list in `research/search-strategy.md`). `Found via` = `<site> search "<query>"` or `<site> saved list`. `Stage` = the **furthest point an application reached**: `sent`, `reply`, `test`, `interview`, `round 2`, `final`, `offer`. Empty until applied; it only moves forward, and the outcome stays in Status.
  - `Last Verified` = the date the posting was last confirmed live.
- `tracker.md`, `tracker-archive.md`, `SHORTLIST.md` — **generated tables, never edit the rows by hand.** After any change run `python tracker.py build .` (on Mac: `python3`). It rebuilds only the tables under the `<!-- rows:… -->` / `<!-- shortlist:… -->` markers; the prose around them stays editable.
- `control-panel.html` — the dashboard. `tracker.py build` regenerates the number strip, the funnel and the top-10 cards; the rest (standfirst, open applications, to-dos) is hand-written by Claude. `python dashboard_server.py` serves it at http://localhost:8090, where the Applied / Not interested buttons write straight to `tracker.csv`.
- `research/` — `job-leads-YYYY-MM-DD.md` (one note per search session), `search-strategy.md`, `search-log.csv` (one line per query), `daily-volume.csv` (one line per site per session), `search-performance.md` (generated by `python research/search_report.py`).
- `interview-prep/` — one note per interview.
- `backups/` — the first build of each day zips the tracker data here (not in git).

Helpers:
- `python tracker.py dedupe . <LinkedIn ID or company>` — before logging a lead: is it already in the tracker, the notes or the archive?
- `python tracker.py stale .` — TO APPLY rows not re-verified in 30 days (the build auto-archives them).
- `python tracker.py render <in.html> <out.pdf>` — CV or letter to PDF with Chrome; refuses to overwrite a PDF newer than its HTML and flags more than one page or a font that isn't Arial.

## Searching for leads

**Order of work in a search session:**

1. **Saved lists first.** I save jobs on my phone between sessions; read them before any keyword search, using the Playwright browser: LinkedIn `linkedin.com/my-items/saved-jobs/` (paginate to the end) and Jobat `jobat.be/nl/jobs/results?favorites=1`. If a site shows a login page, stop and ask me to log in in the Playwright browser window.
2. **Keyword sweeps**, following `research/search-strategy.md`. **Always pair a role term with a sector term**: a bare title returns mostly noise. Search Dutch and English.
3. **For every hit:** `python tracker.py dedupe . <ID / company>`, check the employer's own careers page for the real title and req number, **live-verify**, then score with the rubric in `SHORTLIST.md`, penalties written out.
4. **Log:** score 6+ → a new `tracker.csv` line (Section `1`, at the top, Last Verified = today, `Family` and `Found via` filled in) plus a `leads/<id>-<slug>.md` note whose first paragraph names the source and query **and the full posting URL** (the dashboard's "Open the posting" link is built from it). Below 6 → one "checked and not logged" line with the blocker in today's research note, so it isn't re-found.
5. **Log every query** in `research/search-log.csv` (including ones that returned nothing), and one line per site in `research/daily-volume.csv`.
6. `python tracker.py build .`, then refresh the hand-written parts of `control-panel.html`.

**Where to search (Belgium):**

| Source | How | Notes |
|---|---|---|
| **LinkedIn search** | WebFetch `be.linkedin.com/jobs/search?keywords=<terms>&location=Belgium` | Works without a browser. `&f_TPR=r86400` = last 24 h. Ask for the numeric job IDs, then fetch each job. |
| **LinkedIn job view** | WebFetch `be.linkedin.com/jobs/view/<id>` | Seniority tag, applicant count, full requirements, whether it's still open. Cheaper than the browser. |
| **VDAB** | Playwright: `https://www.vdab.be/vindeenjob/vacatures?trefwoord=<query>&sinds=1&ervaring=1&sort=standaard` | `sinds=1` = today or yesterday, `ervaring=1` = no experience needed (`2` = limited). **Dutch titles only**; English titles come back near-empty. Job links `/vindeenjob/vacatures/<id>/…`: the id is the dedupe key. |
| **Jobat** | Playwright: `https://www.jobat.be/nl/jobs/results/<query-as-slug>?online=3d` | Slug like `sales-engineer`. Sector-combined slugs often return zero. |
| **StepStone** | Playwright: `https://www.stepstone.be/jobs/<query-as-slug>?ag=age_1` | The age filter is unreliable: read only cards that say "N hours ago". Cards appear twice in the page. |
| **Company career pages / ATS** | WebFetch | Workday, Greenhouse, Lever, SmartRecruiters, SuccessFactors. |
| **WebSearch** | | US-tuned; use it to find a URL, not to read a posting. |

Browser sites render with JavaScript: wait ~3 seconds after navigating before reading, and **ignore the total in the page header** (often unfiltered); read the cards themselves. When done with the browser, close it (`browser_close`).

**Live-verify before logging or presenting.** Never add a TO APPLY row or present a lead unless it's confirmed live: an active apply button, or a dated listing from the last ~30 days. 404, a redirect to a generic careers page, "no longer accepting" or "niet meer beschikbaar" → don't log.

**Job titles differ between sites.** Before logging, check the company's own careers page and record the employer's title and req number. A LinkedIn job ID far below this month's range plus a high applicant count usually means an old, evergreen posting.

**Recruiters:** an agency that keeps placing you is one relationship, not one row per vacancy. Keep one canonical row per recruiter and add new vacancies as notes under it (and add that row number to `RECRUITER_ROWS` in `tracker.py` so it never auto-archives).

## Keep the tracker current, in the same turn

Whenever something about an application changes during a session, update it in that same turn, without being asked:

- **Triggers:** a recruiter or employer mail is read; something is drafted, sent, or confirmed as sent; a date is set or moves; the status changes (no reply after 2 months → WITHDRAWN (no response)).
- **How:** prepend a dated paragraph to the lead note (`📧 **YYYY-MM-DD:** …`), update `Status` and `Stage` in `tracker.csv`, run `python tracker.py build .`. Don't rewrite older notes.
- **Record what actually happened.** A draft is "drafted, not sent" until I say I sent it or it shows up in Gmail Sent.
- **Mention the update in one line** at the end of the reply ("Tracker: #12 → INTERVIEWING, 14 Nov 10:00").
- **Dashboard buttons:** a lead note that says "marked on the dashboard" was clicked on the dashboard. Ask which CV and route I used if follow-up needs it.

**Mail check (if Gmail is connected):** on the first job-related prompt of a session, search Gmail (inbox and Sent) for recruiter and employer mail since the newest dated note in `leads/`, apply the updates above, and open the reply with a short "New since last time" list.

**Calendar (if Google Calendar is connected):** every new interview, call-back or deadline also gets a 30-minute event (`Interview: <Company> (<Role>)`). Check the calendar for conflicts before confirming any time.

## Never send anything

**Claude drafts; I send.** No mails, LinkedIn messages, InMail, connection requests, application forms or calendar invites. Gmail sending is blocked in `.claude/settings.json`; drafts are fine. Uploads and "attach" buttons can send immediately (attaching a file to a LinkedIn message sends it on the spot), so never use them. If a draft needs a fact only I have (availability, a date), ask instead of inventing one.

Every application mail ends with an **Attachments** block naming the exact files. When I say I'm about to send, check it in one line: "CV + letter attached?".

## CVs and cover letters

- **Start every CV from `profile/CV_base.html`.** Copy it into `applications/<company>/`, tailor it there, render with `python tracker.py render <cv>.html <cv>.pdf`.
- **Never add a skill or experience I don't have.** If a role wants something I lack, ask me and flag it; never insert it silently. `profile/profile.md` is the only source.
- **Never write my gaps into an application.** No "although I lack", no apologies for missing experience. Gaps go in the lead note as prep material, not in the CV or letter.
- **Check what the company actually sells** before choosing which experience to highlight: relevance comes from their portfolio, not from what sounds technical.
- **Tailor by reordering and emphasis** in the Profile paragraph and the skills line; group the skills line by kind (technical, people, working style, then licence and languages).
- **Match the language of the posting.** English posting → English CV and letter; Dutch posting → Dutch; French → French. Decide from the posting itself, not from the company's nationality.
- **Exactly one page, Arial**, minimal white space; adjust spacing, never the layout.
- **Profile: four sentences max, no bold.** Bold only in the Experience bullet lead-ins. No bold in cover letters.
- **Letters:** don't open with "Please accept my application" / "Graag solliciteer ik"; the first sentence carries the hook. Don't explain the employer's own products to them. Use "my" for your own experience. Close by thanking them for their time. English letters open "Dear Hiring Team," unless a contact's name is known.
- **Prose:** let sentences run to a natural length (~15–20 words, varied), few commas, no spaced dashes, and avoid stacking sentences that start with "I".
- **LinkedIn Easy Apply = no cover letter** (there's nowhere to attach it). Check the apply route before drafting.
- **Never overwrite a PDF someone may have annotated.** If a PDF is newer than its `.html`, someone may have commented on it: stop and ask (`tracker.py render` refuses on its own). Reviewers comment on a copy.
- **File names:** `<First Last> CV <short job title> (<Company>).pdf` and `<First Last> Cover letter <short job title> (<Company>).pdf`.

## Interview prep

Every prep note in `interview-prep/` contains:

1. **My education mapped onto their portfolio**, product by product, in a table: which course or project speaks to which of their products.
2. **My experience mapped onto the skills the role needs**: what I did, the skill it proves, why this job needs it.
3. **A "reread what you sent them" step** naming the exact files, flagging anywhere the CV and the prepared story diverge.
4. Tailored answers to *"How would you prepare for this job?"* and *"What would be your first steps?"*, in the interview's language.
5. The interviewer's name and role, the objections they might raise with answers, and questions to ask back.
6. For roles with prospecting or a sales roleplay: a prospecting/cold-call section and a roleplay plan (ask questions first, link the customer's answers to the solution before naming it).

## Lead hygiene

- **Below 6/10 is never logged as TO APPLY**; it goes in the day's research note as "checked and not logged" with the blocker.
- **Auto-archive:** `tracker.py build` moves TO APPLY rows whose Last Verified is older than 30 days to the archive. Re-verifying a lead = updating its Last Verified date.
- Every `research/job-leads-*.md` file ends with:

  ```
  ---
  [Tracker](../tracker.md) - [Shortlist](../SHORTLIST.md)
  ```

## My rules

Personal scoring penalties, companies to skip, regions, things I've decided. Add each one with its date, and the reason, so Claude can apply it consistently. Examples of the kind of rule that helps:

- *(YYYY-MM-DD)* −2 for roles whose daily work is <something you don't want>.
- *(YYYY-MM-DD)* Don't log <Company> again: rejected, not retrying.
- *(YYYY-MM-DD)* Internships and traineeships: −2, I want a job, not a programme.
